1. Executive Summary

The AI Study Companion is a high-performance, strictly-grounded educational intelligence platform built to solve the core limitations of standard conversational AI in academic and technical domains: hallucinations, lack of citations, and absence of structured knowledge retention.

The platform implements an end-to-end learning loop: students ingest academic PDFs into private, cryptographically isolated project spaces; the system constructs high-density semantic vector representations; students interact with a strictly grounded AI Tutor backed by page-level citations; adaptive quizzes calibrate cognitive mastery across Bloom’s Revised Taxonomy; and an algorithmic synthesis engine generates structured, printable exam revision cheat sheets.

Core Architectural Tenets
1. Zero-Hallucination Grounding: Every tutor response is constrained to retrieved document chunks with mandatory page and quotation anchors.
2. Multi-Tenant Project Isolation: Strict relational and vector boundary isolation prevents data leakage across project workspaces.
3. Cognitive Adaptation: Mastery scores evolve dynamically using Bayesian updates, categorizing concepts into Improving, Stable, and Requiring Attention.
4. Production Observability: Full telemetry tracing every prompt token, completion token, latency percentile, and estimated API cost.

3. Detailed Subsystem Workflows & Data Flows

3.1 Document Ingestion & Dense Vector Indexing Pipeline

The ingestion subsystem transforms raw unstructured PDF files into searchable, grounded vector embeddings through a deterministic 5-stage pipeline:

[Upload PDF] ──► [SHA-256 Checksum] ──► [PyMuPDF Page Extraction] │ ▼ [pgvector Bulk Upsert] ◄── [BGE 384-dim Vectors] ◄── [Sliding-Window Semantic Chunking] │ ├─ Unique Constraint: (material_id, chunk_index) ├─ HNSW Cosine Distance Index: vector_cosine_ops (m=16, ef=64) └─ Concept Extraction ──► Auto-Seeds Initial Knowledge Graph Nodes ──► Status: READY
  • Stage 1 (Extraction): PyMuPDF extracts raw text per page while recording structural metadata (page number, bounding dimensions, character counts).
  • Stage 2 (Semantic Chunking): Implements sliding-window chunking targeting 400 tokens (~1600 chars) with a 50-token overlap, preserving semantic context across page boundaries. Each chunk is tagged with its source section header.
  • Stage 3 (Embedding Generation): Utilizes FastEmbed with BAAI/bge-small-en-v1.5 to produce high-density 384-dimensional dense vectors.
  • Stage 4 (Vector Indexing): Chunks and embeddings are bulk-inserted into PostgreSQL with an HNSW index, guaranteeing sub-50ms nearest neighbor queries.
  • Stage 5 (Concept Extraction): Automatically generates initial high-yield conceptual anchors for the project knowledge graph.

3.2 Grounded AI Tutor & Citation Flow

The Tutor subsystem eliminates hallucinations by enforcing strict evidence retrieval prior to prompt injection:

[Student Query] ──► [384-dim Query Embedding] ──► [Project-Isolated pgvector Cosine Search] │ ▼ [Response to Student] ◄── [Gemini 2.5 Flash Generation] ◄── [Grounded Prompt Assembly] │ │ └─ Includes Verified Citations: └─ Enforces: "Cite exact page # [DocName.pdf, Page 14, "Quote"] and quote verbatim."

3.3 Adaptive Cognitive Mastery & Knowledge Tracing

The assessment engine monitors student understanding dynamically across quizzes:

  • Bloom's Taxonomy Calibration: Questions span four levels: Remembering/Understanding (0.6 weight), Application (0.8 weight), and Analysis/Evaluation (1.0 weight).
  • Bayesian Update Formula: Upon correct answer: M_new = M_old + (100 - M_old) × 0.15 × W_diff. Upon mistake: M_new = M_old - (M_old × 0.20 × W_diff).
  • Growth Trend States: Automatically classified into IMPROVING (upward velocity), STABLE (consistent mastery >65%), and REQUIRING_ATTENTION (<50% or consecutive errors).

5. Security, Isolation & Multi-Tenancy

  • Strict Isolation Proof: Vector retrieval is mathematically bounded by WHERE project_id = :project_id. Automated unit test test_project_a_never_leaks_project_b_chunks validates in CI that higher-similarity vectors belonging to other projects are never returned.
  • Authentication: HMAC-SHA256 (HS256) JWT tokens with direct bcrypt password hashing and salted digests.
  • Cloud URL Normalization: The engine automatically adapts cloud-injected PostgreSQL connection strings (Render/Neon/Supabase) to native asynchronous postgresql+asyncpg:// pools.
